# Визарно

Личный кабинет продавца для анализа и создания карточек ноутбуков. Сервис сохраняет профиль товара, исходные изображения, результаты анализа, ТЗ дизайнеру и готовые серии PNG.

## Запуск

Запустите Docker Desktop, откройте PowerShell в папке с этим README и выполните:

```powershell
docker compose up --build -d
```

Откройте http://localhost:5188 и нажмите «Создать аккаунт». Для остановки выполните `docker compose down`. Именованный том PostgreSQL сохраняет кабинеты и историю версий между запусками.

## Демонстрация

1. Создайте товар без обложки. Для пилота с ноутбуком укажите модель и подтверждённое значение «без ОС» с источником.
2. Добавьте версию с обложкой, заголовком предложения, описанием и при наличии слайдами галереи. Обложка — первое изображение, далее идут слайды 2–5. Подпись к слайду вводится продавцом. В анкете можно указать задачу «первый видеоурок утром».
3. Откройте «Результат анализа». Раскройте замечание, проверьте его основание и отметьте правки для дизайнера. Кнопка «Скачать ТЗ (.txt)» сохраняет текст из предпросмотра.
4. Загрузите следующую версию того же предложения с пояснением про установку системы. Сравните статусы правил с выбранной прошлой версией. Исторический статус зафиксирован в момент загрузки, текущий учитывает актуальный профиль.

## Создание готовых карточек

1. Сохраните профиль ноутбука и загрузите исходную обложку. Значения должны относиться к конкретной конфигурации; источник указывает продавец, сервис не подтверждает достоверность производителя автоматически.
2. При желании запустите визуальный разбор. Помимо ТЗ, нейросеть выберет для каждого слайда композицию, палитру, исходное фото и область товара. Старые сохранённые разборы без плана генерации нужно запустить заново.
3. В разделе «Готовые карточки» проверьте текст, выберите фото или загрузите чистый снимок товара. При необходимости обрежьте скриншот. Автоматическую область, предложенную ИИ, можно заменить ручной.
4. Для выпуска заполните анкету в материалах версии. Укажите аудиторию, задачу, мотив, тезис обложки, ключевое свойство из профиля, преимущество, пользу и источник. В генерации выберите проверяющий сервис и нажмите «Создать карточки». Сервис получит изображения итоговых слайдов, анкету и сведения о товаре. При замечаниях исправьте текст, фото или оформление и повторите проверку.
5. Скачайте нужные слайды или нажмите «Сохранить серию в кабинете». В разделе «Личный кабинет → Мои серии» доступны все сохранения, включая предыдущие варианты одного товара. Откройте серию по обложке, выберите миниатюру и скачайте PNG. После изменения исходных данных у серии появится пометка. Пароль и удаление аккаунта находятся во вкладке «Настройки».

Изображения собираются из фотографий продавца и текста плана. Для сцены использования загрузите соответствующий снимок. Для отдельного слайда можно выбрать фото из галереи и палитру по цветовой памятке. Для выпуска любой новой серии нужен настроенный сервис проверки. Без ключа доступны профиль, локальный анализ и подготовка ТЗ.

Проверяются все правила и три режима просмотра из `backend/psychology.md`. Для каждого применимого правила требуется основание на слайде, для условного пропуска — причина. Скачивание открывается после положительного отчёта. При сохранении сервер сверяет хэши проверенных PNG в исходном порядке, владельца, версию, профиль и редакцию методики. Отчёт доступен в кабинете. Старые серии отмечены как архивные. Визуальные критерии оценивает модель; реакция покупателей проверяется отдельно в исследовательском пилоте.

Go принимает PNG, проверяет формат, размеры, актуальность профиля и владельца. В PostgreSQL таблицы `generated_sets` и `generated_pages` хранят серии и изображения. Они удаляются вместе с аккаунтом. Исходные версии и готовые результаты хранятся раздельно.

## Как устроено

React обращается к Go по `/api` на том же адресе. Go декодирует файл, вычисляет размеры и вес, сохраняет обложку и отчёт в PostgreSQL одной транзакцией. Отчёт привязан к загруженной версии. В таблице `sellers` хранятся email, соль и хэш пароля, в `sessions` — хэши токенов сессий. Таблица `cards` связывает товар с продавцом, а `versions` хранит файлы, отчёты и время проверки. Доступ к изображениям и версиям проверяется сервером.

Для локальной демонстрации приложение доступно только через loopback. Настройки подключения находятся в `compose.yaml`. При развёртывании под HTTPS задайте приложению `COOKIE_SECURE=true` и используйте собственный пароль БД.

## Что оценивается

Без ключа доступны технические измерения, проверка расхождений в профиле, заголовка, нескольких рекламных формулировок, задачи из анкеты и явных пояснений об установке ОС. Поиск по тексту использует словарь и шаблоны. Непереданное описание обозначается в отчёте. Короткая сторона от 800 пикселей и вес обложки до 2 МиБ — внутренние ориентиры. Изображения хранятся в PostgreSQL с проверкой владельца при чтении.

Дополнительный разбор по методике психолога учитывает материалы конкретной версии. Сервер проверяет ссылки на переданные источники и наличие цитат в заголовке и описании. Визуальные наблюдения сверяют с изображениями. Сравнение статусов описывает изменения карточки. Понимание покупателями проверяется отдельно в исследовательском пилоте.

## Тесты

В папке `backend` выполните `go test -v ./...`. Для полного теста задайте `TEST_DATABASE_URL` со строкой подключения к **отдельной тестовой базе** PostgreSQL. Тест создаёт в ней пользователей, карточку и версии и проверяет ограничения доступа. Без этой переменной запускаются только проверки анализа изображений.


## Резервная копия в PowerShell

Откройте папку проекта и запустите сервис базы данных. В той же сессии PowerShell выполните:

```powershell
docker compose up -d --wait db
$backup = .\scripts\backup.ps1
$backup
```

Архив в формате PostgreSQL custom появится в папке `backups`. Он включает аккаунты, хэши паролей, карточки, изображения и отчёты. Содержимое таблицы сессий исключено, поэтому после восстановления нужен новый вход. Для защиты от потери диска храните дополнительный экземпляр архива отдельно, с ограниченным доступом.

## Восстановление и проверка

```powershell
$restored = .\scripts\restore.ps1 -Backup $backup
$restored
docker compose run --rm --no-deps -p 127.0.0.1:5190:8080 -e "DATABASE_URL=host=db port=5432 user=vizarno dbname=$restored sslmode=disable" app
```

Если PowerShell открыт заново, вместо переменной `$backup` укажите путь к файлу .dump. Для последней команды нужен собранный образ приложения (`docker compose build app`). Откройте http://localhost:5190, войдите старым паролем, откройте карточку и сравните версии. Основной кабинет по-прежнему использует базу vizarno. Тестовая база создаётся в том же экземпляре PostgreSQL с новым именем при каждом запуске. Ctrl+C останавливает проверочное приложение. Имя базы, которую нужно оставить или впоследствии убрать, выводится в `$restored`.

Для локального PostgreSQL без Docker оба скрипта принимают `-LocalPostgres`. Утилиты PostgreSQL 18 должны быть в PATH. Подключение задаётся через PGHOST, PGPORT, PGUSER и при необходимости PGPASSWORD. PGDATABASE задаёт исходную базу для копирования. Используйте сервер с правом создания отдельной базы при восстановлении.

## Браузерный тест кабинета

Откройте PowerShell в папке frontend. Запустите приложение и выполните:

```powershell
npm ci
npx playwright install chromium --only-shell
$env:VIZARNO_TEST_URL = "http://127.0.0.1:5190"
npx playwright test tests/account.spec.mjs --workers=1
```

Адрес 5190 подходит для копии из предыдущего раздела. Без переменной тест открывает локальный порт 5188. Тест регистрирует отдельный адрес в домене example.test, делает выход и вход, проверяет email в кабинете, меняет пароль и удаляет тестовый аккаунт.

## Выбор нейросети для разбора обложки

В файле `.env` рядом с `compose.yaml` укажите ключи тех сервисов, которые хотите включить. Достаточно одного.

- `GEMINI_API_KEY` — Google Gemini 3.1 Flash-Lite. Есть бесплатная квота в поддерживаемых регионах. На бесплатном тарифе Google может использовать материалы для улучшения продуктов. [Получить ключ](https://aistudio.google.com/apikey) · [Условия тарифа](https://ai.google.dev/gemini-api/docs/pricing#gemini-3.1-flash-lite)
- `GROQ_API_KEY` — Groq с моделью Qwen для анализа изображений. У бесплатного плана есть ограничения по запросам и токенам. [Получить ключ](https://console.groq.com/keys) · [Лимиты](https://console.groq.com/docs/rate-limits)
- `OPENAI_API_KEY` — ранее подключённый вариант с тарификацией аккаунта OpenAI. Для него можно задать `OPENAI_MODEL` (по умолчанию `gpt-4.1-mini`).
- `OPENAI_IMAGE_MODEL` — модель, которая создаёт итоговые изображения слайдов из исходного фото. По умолчанию `gpt-image-2.5-sunburst`. В мастерской можно переключиться между нейрогенерацией OpenAI и точной локальной сборкой.

Режим по умолчанию — «Дизайн-система Визарно». Он локально создаёт PNG 1200 × 1600: единая брендовая шапка, крупный тезис, предметный центр, CTA на обложке, ситуационный слайд и карточки подтверждённых характеристик. API генерации изображений для этого режима не нужен.

Для Groq добавьте строку `GROQ_API_KEY=ваш_ключ` и выполните `docker compose up --build -d`. Откройте карточку с обложкой, выберите сервис и нажмите «Дополнить ТЗ визуальным разбором». Последний успешный разбор сохраняется для этой версии, профиля и набора локальных правок. При ошибке доступны локальные результаты. Визуальные замечания можно отметить перед экспортом.

Ключи читает только Go. По нажатию кнопки он передаёт выбранному сервису план, материалы предложения (тексты, обложку, галерею) и применимые правила методики. При обновлении методики актуализируйте правила в `backend/psychology.md`.
